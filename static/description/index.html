BlueNova Backend Theme

A premium visual reskin of the Odoo 19 backend.

Persistent app sidebar, light/dark mode, a themed login / signup / reset-password flow, an optional public home page, a KPI landing dashboard, and an in-app Settings screen for recolouring everything — no SCSS edits, no asset rebuild.

Deep Indigo #3959b0    Ocean Blue #0284c7

Activate the app and the theme applies to the whole web client. Uninstall it and Odoo goes back to its stock look — no data is touched.

Design system

  • Design tokens — a single set of --cmt-* CSS custom properties drives every colour, radius, shadow and font in the theme
  • Palette — Deep Indigo primary with Ocean Blue accents over tiered white surfaces, fully overridable per-instance from Settings
  • Typography — Inter for UI text, Poppins for labels and numerics, both bundled in-module as latin-subset woff2 (no fonts.googleapis.com request, nothing breaks offline or under a strict CSP)
  • Shape & elevation — 8/12/16px radii, soft multi-layer shadows, glassmorphic panels, cards and dropdowns
  • Top navbar restyled through Odoo's own --NavBar-* custom properties, so core keeps control of layout and the theme only supplies colour
  • Responsive — tablet and phone breakpoints mirroring Bootstrap's; below md the rail steps aside for Odoo's own slide-in app menu

Interface

  • Persistent app sidebar replacing Odoo's apps dropdown — every app the user can reach, always visible, current app marked by an accent spine. Toggled from the navbar's grid button; open/closed state remembered per browser
  • 55+ bundled app icons, single-colour and painted through a CSS mask (grey at rest, blue on hover, a stronger blue for the app you're in) — matched by module name, so the mapping keeps working regardless of the user's language. Apps without bundled artwork fall back to their own Odoo icon, then to a neutral placeholder
  • Light / dark mode, switched from the sidebar footer, applied instantly, remembered per browser. A single data-cmt-theme attribute on <html> covers dialogs, popovers and tooltips too — no server round-trip, no bundle rebuild
  • Control panel styled as a page header
  • Kanban board — 320px stage columns, glassmorphic cards with an accent spine
  • CRM pipeline stat banner above the pipeline, computed entirely from data already in memory (no extra RPC)

Settings → Theme Settings

  • Live colour pickers for the core palette, top bar, search box, sidebar, active-app highlight and semantic colours (info / success / warning / danger) — each with its own dark-mode counterpart where the surface needs one
  • Uploadable brand image for the sidebar and a login background image (light and dark), stored as attachments rather than inline, so no base64 payload rides along on every request
  • Hero typography controls (title / lead size and weight) for the public home page
  • Export / Import / Reset — download the current palette as a JSON preset, re-import it later (validated field-by-field before anything is written), or reset to the compiled defaults
  • Every colour is validated against a strict hex / rgb() / rgba() pattern before it is saved and again before it is rendered into the page
  • Changes apply on save via a page reload — no asset-bundle rebuild, no server restart

Themed dashboard, login, signup and public page

  • KPI dashboard — tiles for open opportunities, quotations, RFQs, posted invoices, open tasks, transfers to process and active employees. Each tile is dropped silently if its app isn't installed or the current user can't read it, and counts records as that user — never sudo() — so record rules apply exactly as they do in the underlying list view. Can optionally open right after login
  • Login, signup and reset-password pages pick up the same palette, plus an optional logo and tagline — and keep that styling even once the Website app is installed
  • Optional public page at "/" for anonymous visitors — off by default, and it stands down automatically once the Website app is installed, since that app owns "/" properly

Safe by design

The module adds a small settings model, a transient import wizard, and two opt-in controller hooks (login redirect, public home page) — no new stored business data. Its only persisted state is that transient wizard plus a handful of configuration rows and attachment images holding the chosen palette. It can be activated and removed at any time without migrating or losing data.

Known limits

  • Odoo's slide-in app menu on small screens (below md) is left as-is.
  • Graph views stay light on purpose. Odoo draws chart axis labels onto the canvas from JS using a colour that Community pins to "light" server-side, so darkening the panel would put near-black text on a near-black background — the chart keeps an explicit light card instead.
  • Dark mode covers the surfaces this theme styles plus the main list / form / kanban / dialog chrome. Odoo compiles most other colours into SCSS, so deeper corners — some reports, iframes and third-party widgets — can still show light patches.
  • The public home page has no drag-and-drop editing; it renders the company's own data plus the Settings tagline.
  • No fixed bottom footer bar and no floating action button.

Uninstall

Apps → BlueNova Backend Theme → Uninstall. The backend returns to stock Odoo immediately. The module owns no business models or records, so nothing is left behind but the saved palette and images, which are removed with it.
